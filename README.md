## В папке backend лежит только серверная логика, в папке фронтенд лежит все что связано с клиентом, там лежит вся геймдев логика. это два отдельных сервиса.

## Все серверные данные и взаимодействие с бд лежит в /backend


Общие правила:

если будут даже какие то минимальные вопросы
перед планированием задачи - спроси их.
после каждого пласта изменений делай коммиты и сразу пуш. замечания по архитектуре и коду: везде используй ооп и клин код, всегда выбирай абстракция и
только потом реализацию. все переменные окружения выноси. после того как
закончишь выполнение фичей запусти агентов тестировщиков.

- Один класс — одна ответственность. Класс > 200 строк или метод > 30 строк —
сигнал разделить.
- Зависимости только через конструктор (primary constructors). Никакого Service Locator,
никакого IServiceProvider в бизнес-коде, никаких статических изменяемых полей.
- Классы по умолчанию sealed. Наследование — только для закрытых иерархий record.
- Предпочитай композицию наследованию.
- Один публичный тип — один файл. File-scoped namespaces.
- Регистрация DI — в extension-методах по модулю: `services.AddTelegram(config)`,
`services.AddBitrix(config)` и т.д.

- Никаких магических строк и чисел: коды полей Битрикса, лимиты, задержки — в Options
или именованных константах.
- Секреты — только из env / user-secrets, никогда в коде и appsettings.json.

- Весь I/O асинхронный, async до самого верха, никаких .Result / .Wait().
- CancellationToken — последним параметром в каждом async-методе и пробрасывается вниз.
- Долгие процессы — через BackgroundService; очереди — через System.Threading.Channels.
- HttpClient — только через IHttpClientFactory / typed clients.

- ILogger<T> со структурированными сообщениями:
`logger.LogInformation("Lead {LeadId} handed off to broker {BrokerId}", ...)`.
Никакой интерполяции в шаблоне.
- Никогда не логируй секреты, коды входа, пароли 2FA, полный текст личных сообщений
вне демо-режима.

- Nullable reference types включены, предупреждения = ошибки.
- record для DTO и неизменяемых данных, init-only свойства, коллекции IReadOnlyList.
- Современный C#: primary constructors, collection expressions, pattern matching,
switch-выражения, required-члены.
- Имена — по смыслу домена (Lead, Slot, Handoff), а не технические (Manager, Helper, Util).
Классы с именами *Manager, *Helper, *Utils запрещены.
- У каждого класса и у каждой функции должны быть комментарии в xml формате



- Не пиши НИКАКИЕ тесты
