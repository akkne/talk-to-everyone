# Мониторинг

Docker Compose поднимает Prometheus, Loki, Grafana и Grafana Alloy вместе с игрой. После запуска откройте `http://localhost:3000` на компьютере-хосте. Логин и пароль задаются `GRAFANA_ADMIN_USER` и `GRAFANA_ADMIN_PASSWORD` в `.env`; перед использованием задайте собственный пароль. Grafana доступна только с хоста, порты Prometheus и Loki наружу не публикуются. Источники данных и панель **Игра · состояние и ошибки** создаются автоматически.

Prometheus каждые 15 секунд собирает `/metrics` бэкенда. На панели видны: доступность API, число игроков, лобби и матчей, активные SignalR-соединения, скорость и ошибки HTTP, длительность запросов, число и длительность генераций NPC, создания лобби, входы, старты и кики. Отклонённые игровые команды учитываются в `game_hub_rejections_total` с названиями операции и причины. Активные игроки/лобби/матчи обновляются из базы раз в 15 секунд. Счётчики событий начинаются заново после перезапуска бэкенда; для долгого периода используйте `increase(...)` в Grafana. Метрики не содержат имён игроков, кодов комнат или идентификаторов сессий.

Alloy считывает Docker-логи контейнеров этого Compose-проекта и отправляет их в Loki. На панели показаны логи бэкенда; остальные сервисы доступны через Grafana Explore по метке `service_name`. Имя проекта Compose по умолчанию `talk-to-everyone`; если задаёте `COMPOSE_PROJECT_NAME`, Alloy использует его же для фильтра. Логи Loki хранятся 7 дней, метрики Prometheus — 15 дней. Данные лежат в именованных томах Docker.

Для ручного запуска бэкенда `/metrics` доступен на его HTTP-порту. Grafana и сборщик логов в этом режиме сами не запускаются. Проверка конфигурации без запуска контейнеров: `docker compose config`.
