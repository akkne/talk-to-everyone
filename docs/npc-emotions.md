# Эмоции и анимации реплик NPC

LLM выбирает `emotion` по смыслу собственного ответа, вопросу и характеру NPC. Код из JSON становится командой позы, жестов, мимики и значка над головой. Используется действующий контракт `NpcSay`, миграция базы не нужна: `GameMessage.Emotion` уже сохраняется и попадает в `StateSnapshot.chat`.

| Код LLM | Поведение |
| --- | --- |
| `neutral` | 💬 Спокойная жестикуляция и кивки при объяснении |
| `happy` | 😄 Раскрытые руки, оживлённые жесты и покачивание |
| `sad` | 😔 Опущенная голова, сдержанные движения рук |
| `angry` | 😠 Наклон вперёд, поднятые руки, резкие жесты и нахмуренные брови |
| `surprised` | 😲 Руки у лица, отклонение назад, открытый рот |

Первые 550 мс NPC показывает эмоцию, а чат — её название. Затем одновременно появляются текст над персонажем и реплика в чате; персонаж жестикулирует и двигает ртом. Длительность зависит от длины текста: 3,5–10 секунд речи после реакции, в последние 300 мс поза и значок плавно исчезают. Движение не меняет позицию персонажа и совместимо с прыжками игроков.

Одна очередь сцены сохраняет порядок всех поступивших `NpcSay`, включая быстрые ответы разных NPC и повторные реплики одного NPC. Повторные ID не воспроизводятся. Одинаковый путь используется в раундах 1–3, допросе игрока в раунде 4 и перепалке NPC в раунде 5. Неизвестная/пустая эмоция получает `neutral` и полноценную жестикуляцию. Поддерживаются старые коды `CHILL`, `ROFL`, `SMIRK`, `SWEAT`, `FACEPALM`, `RAGE`, `SHOCK`.

При смене/окончании раунда выступления отменяются, а весь уже полученный текст сохраняется в ограниченной ленте. Удаление NPC отменяет его выступления. Переподключение загружает историю без повторного проигрывания старых анимаций. Сброс игры очищает очередь без отложенных таймеров.

## Этапы и проверки

1. **Команды LLM и последовательность речи.** Тесты настоящего `LlmClient` проверяют схему JSON, семантические инструкции, пять эмоций, старые коды, некорректный тип и все автоматические раунды. Тесты очереди проверяют задержку до текста, длительность, порядок 10 быстрых реплик, дедупликацию и паузу вкладки.
2. **Анимации и значки.** Пять различных поз, жесты, реакция до текста, удаление текстур, плавное завершение, замена реплики и совместимость с прыжком/позой сидя. Комбинация этапов 1+2 проверяет реальный `Npc` с командами эмоций и временем очереди.
3. **Игровая интеграция.** Тест настоящего `RoundDirector` в раунде 5 проверяет последовательность `NpcThinking` → `NpcSay` для двух NPC, историю предыдущего собеседника, сохранение эмоций и отправку событий SignalR. Клиентские тесты проверяют обработчики событий, вопросы игрока, переподключение, удаление NPC и смену раунда. Комбинация 1+2+3 проигрывает 10 реплик через настоящий store и реальные модели `Npc`, проверяя эмоцию до текста и синхронное раскрытие чата и облачка.
4. **Общий прогон.** Все frontend/backend тесты, включая прежние проверки движения, TypeScript и production-сборки. Визуальный стенд использует настоящие `Scene`, `Npc`, store и `Chat`.

Команды из корня репозитория (нужны Node.js и .NET 10):

```powershell
# Этап 1
dotnet test tests/Backend.Dialogue.Tests/Backend.Dialogue.Tests.csproj --filter FullyQualifiedName~LlmEmotionTests
Set-Location frontend
node --test tests/dialogue.test.mjs

# Этап 2 отдельно, затем 1+2
node --test tests/expressions.test.mjs
node --test tests/dialogue.test.mjs tests/expressions.test.mjs

# Этап 3 и комбинация 1+2+3 на клиенте
node --test tests/dialogue-integration.test.mjs
node --test tests/expressions.test.mjs tests/dialogue-integration.test.mjs
Set-Location ..
dotnet test tests/Backend.Dialogue.Tests/Backend.Dialogue.Tests.csproj --filter FullyQualifiedName~RoundFiveTests

# Общая регрессия и сборки
dotnet test tests/Backend.Dialogue.Tests/Backend.Dialogue.Tests.csproj
dotnet build backend/Backend.csproj --configuration Release
Set-Location frontend
npm test
npm run build

# Визуальная проверка
npm run dev
# Открыть http://localhost:5173/tests/emotions-preview.html
```

На стенде можно отдельно запустить каждую эмоцию и очередь «Перепалка: 5 реплик». Он лежит в `frontend/tests`, не импортируется приложением и не попадает в production-сборку.

В автоматических backend-тестах транспорт LLM заменён детерминированными JSON-ответами, а PostgreSQL — EF InMemory. Они проверяют реальную логику клиента LLM и директора раунда, но не оценивают качество выбора эмоций установленной моделью Ollama. Для проверки с живой моделью запустите обычный матч: задайте провокационный вопрос в раунде 4 и досмотрите перепалку в раунде 5.
