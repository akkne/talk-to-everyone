# Переход к overall и API v2

Сверка 31.10.2026, исходный remote-коммит `712d7bc`. Приоритет: ходьба → сцена и посадка → единый v2 → игровой цикл → проверка с сервером.

Источники: [overall](overall.md), [стык сервисов](integration.md), [API v2](../backend/docs/backend.md). `frontend/PLAN.md` — архив, не текущий план. В `backend/` пока только документация, исполняемого сервера нет.

## Расхождения на момент сверки

| Область | Было в коде | Требуется |
| --- | --- | --- |
| Пространство | Пол, одна стена, общий круглый стол; NPC по дуге | Закрытая студия, два яруса по пять NPC, рампы, кресла и маленькие столы полукругом |
| Управление | Только ограниченное вращение сидячей камеры | WASD 2.5 м/с, обзор 360°, коллизии, E, ограничение кресла ±120°, отключение ввода в UI |
| Движение по сети | `SendCamera`, игрок без координат | `SendPose` 10 Гц, `Pose.seq`, предсказание/коррекция, серверные кресла и коллизии |
| Модели | Лица, телесные головы, пульсация реакций | Одинаковые цветные примитивы, номера NPC, имена игроков, значок эмоции |
| Данные | v1: `index`, `started`, `loreChunks`, неполный snapshot | v2: `number`, `anchorId`, `scene`, `seats`, `questions`, `chat`, `reveal`, `scoreboard`, `me.role` |
| Выбор пары | Постоянная доска, перетаскивание, нити, заметки, `LockPair` | В конце 2/3/4 раундов одна новая пара/пропуск, `SubmitPair` и подтверждение сервера |
| Вопросы | Отдельное закрываемое окно лишь в 4 раунде | Постоянное меню номеров, отправка только в 4 раунде; серверный лимит и «Думает…» |
| Восстановление | Реплики с клиентскими ID; лимиты сбрасываются | Полная замена снимком, серверные ID, сохранённые вопросы, выборы, позы и финал |
| Сервер | Документация без приложения | ASP.NET Core, SignalR, PostgreSQL, серверные раунды, роли, LLM, счёт |

## Неоднозначности документации

- В overall одновременно указаны упрощённый выбор и старый драфт-борд. Для MVP используем простые карточки; в API v2 операции черновика остаются, но сложный UI для них не обязателен.
- «После каждого раунда», отсутствие выбора в первом и пять раундов противоречат друг другу. Следуем v2: окна после 2, 3, 4; пятый — вскрытие.
- По текущей формуле максимум 800, не заявленные в overall 1000. Счёт считает сервер.
- Overall упоминает R3F, финальный стек и существующая реализация — прямой three.js. Для ходьбы переписывать рендер не требуется.
- Архивный PLAN требует офлайн Ollama; overall указывает облачный Claude. Провайдер — серверная настройка; до отдельного решения не заявляем офлайн-готовность.

## Этапы и критерии

### 1. Ходьба и студия — выполнено локально

- [x] Публичный `SceneSpec`: пол/потолок/стены, два яруса, две рампы, полукруг кресел; preview использует отдельный локальный spec.
- [x] WASD относительно камеры, одинаковая скорость по диагонали, 360°, ограниченный вертикальный наклон, без прыжков.
- [x] Коллизии с мебелью/стенами/ярусами; движение по рампам, без подъёма сквозь вертикальную грань или падения с края.
- [x] E возле свободного кресла жюри, фиксированная посадка, выход в проход, ±120° в кресле.
- [x] Остановка при открытии UI, потере фокуса и Esc; стрелки как запасной обзор без захвата мыши.
- [x] `SendPose` ≤10 Гц, коррекция по подтверждённому `seq`, `SitDown`/`StandUp`, `SeatState`/`ActionReject`; удалён старый `SendCamera`.
- [x] Проверки механики и сборка; ходьба/посадка проверены в браузере в preview.
- [ ] Проверка сетевой части с реальным v2-сервером. Это подготовленный клиентский код, не проверенная интеграция.

### 2. Полная миграция состояния на v2 — следующий этап

- [ ] Атомарно заменить остальные v1 DTO/события в `types`, store, preview, кэше и UI.
- [ ] `NpcMeta.number`/`anchorId` вместо обязательного `index`; удалить lore из публичных деталей.
- [ ] Полный snapshot: `phase`, nullable `round`, `me.role`, `scene`, `seats`, `questions`, `chat`, `scoreboard`, `reveal`.
- [ ] После reconnect сбрасывать предсказание позы и получать актуальную геометрию; поддержать изменение `scene.version`.
- [ ] `leaderId`/`canStart`, восстановление позднего входа и финала. Исключить отправку команд до снимка.

Критерий: клиент и preview используют только v2; реальные DTO проходят тот же сценарий без адаптера v1.

### 3. Привести игровой UI к MVP

- [ ] История слева, постоянно доступные вопросы справа; отправка лишь в допросе.
- [ ] Удалить нити/перетаскивание/заметки из обязательного сценария; десять цветных карточек и подтверждение одной пары в окне выбора.
- [ ] `SubmitPair {requestId,round,a,b}` / пропуск; ожидание `PairSubmitted`, запрет ранее подтверждённых NPC.
- [ ] `QuestionState`, `QuestionOk`/`Failed`, `NpcThinking`, эмоции значком; история с дедупликацией серверных ID.
- [ ] Убрать пульсацию моделей и декоративные эффекты, сохранить номера NPC при загрузке имени.

Критерий: 1 → 2 → выбор → 3 → выбор → 4 (два разных NPC) → выбор → финал. Таймер клиента не меняет фазу.

### 4. Сервер и сквозная проверка

- [ ] Бэкенд по [серверному роадмапу](../backend/docs/roadmap.md): Auth/полный snapshot, SceneSpec, позы/кресла, раунды, сохранение, LLM, финал.
- [ ] Сервер использует те же объёмы SceneSpec и отклоняет превышение скорости/проход сквозь стены; два клиента конкурируют за кресло.
- [ ] Два браузера: движение, посадка, три выбора, вопросы, финал; reconnect/late join/рестарт восстанавливают состояние.
- [ ] Проверить отсутствие ролей/lore до финала, кэш ≤1 NPC и ≤10% реального объёма мира, таймаут LLM и восстановление попытки.

Критерий: сценарий проходит с реальным сервером и PostgreSQL; preview не считается подтверждением сетевых требований.

## Как проверить текущий этап

`cd frontend && npm test && npm run build`, затем `npm run dev` → «Сначала осмотреть интерфейс» → «Начать расследование» → нажать на сцену. WASD — ходьба; мышь/стрелки — обзор; E — сесть/встать; Esc — интерфейс. Рампы находятся справа от трибуны. Если захват мыши запрещён браузером, работают WASD и стрелки после фокуса сцены.

Сетевое состояние остаётся частично v1: подключение к полноценному v2 hub до этапа 2 не поддерживается. Для live-сцены обязательно поле `scene`, локальная геометрия preview не подставляется вместо серверной.
